# 常见问题与故障排查(FAQ)

> 按现象组织。先看「诊断与日志」窗口的三张健康卡(物理链路 / 门户认证 / 互联网可达)定位问题在哪一层,再对号入座。

## 1. 菜单显示"已联网",但浏览器打不开网页

**几乎总是 Clash/代理的缘故**。浏览器流量走代理隧道出网;PortalKit 显示的"已联网"指的是**物理网卡路径**(Wi-Fi 本身)。可能性:

- 代理节点正常而物理路径被门户拦截 → PortalKit 会显示"连接待验证"并自动认证;若长时间不恢复,见第 2/3 条
- 物理路径正常但目标网站被代理规则分流到了坏节点 → 换节点/重启 Clash

**验证物理路径**:终端跑 `~/PortalKit/.venv/bin/portalkit check --json`,看 `internet` 字段与分层证据(`dns/tcp/http` 各层 pass/fail)。

## 2. 门户提示"认证失败",但账号密码确认无误

按概率排序:

1. **单设备限制(最常见)**:很多学校校园网同一账号只允许一台设备在线。你的手机如果也连着校园网,会把 Mac 踢下线(或反过来)。PortalKit 的防互踢机制会**停止自动重提交**并提示"疑似其他设备抢占"——此时在手机上断开校园网,再点菜单「立即认证」。
2. **Wi-Fi 私有地址(MAC 随机化)**:macOS 默认对每个网络使用随机 MAC。学校若按设备(MAC)绑定认证,会提示"设备未注册"或持续认证失败。**解决**:系统设置 → Wi-Fi → 点当前网络旁 ⓘ → 关闭「私有无线地址」→ 重新连网。
3. **账号状态**:欠费、未实名、需在网页完善信息 → 用浏览器(关掉 Clash 系统代理)打开门户地址手动登录核实;浏览器也失败就找学校网络中心。

## 3. 浏览器打不开门户地址(如 192.168.102.x)

门户是**校园内网地址**,浏览器流量走 Clash 代理时会被送到外部节点,自然打不开。解决:

- 在 Clash 配置里把 `192.168.102.0/24`(或学校网段)加入 DIRECT 规则;或
- 临时关闭 Clash「系统代理」开关,用完再开

PortalKit 自身**不受此影响**——它的所有请求都绑定物理网卡直连。

## 4. 菜单显示"正在识别门户"但一直不认证

分层看「诊断与日志」:

- **互联网可达但门户未识别**:当前网络的门户不在已知适配器覆盖内(比如学校换了新门户系统)→ 菜单「添加 / 确认可信网络…」看能否识别;不行就发诊断给维护者
- **门户已识别且受信但未提交**:可能处于"疑似互踢"保护(见第 2 条第 1 款)或 10 分钟节流期(刚认证成功过)——都是有意设计,防止把你的会话踢掉

## 5. 凭据存在哪?换机怎么迁移?

- 密码存 macOS **Keychain**(服务名 `PortalKit.<适配器>.<门户地址>`),日志/诊断/导出里永不出现
- 换机:新机装应用后,设置 → 「导出配置」(旧机)→「导入配置」(新机)可迁移信任网络与设置;**凭据出于安全不导出**,每个网络重录一遍

## 6. 应用消失了/崩溃了?

LaunchAgent 会在应用异常退出后约 10 秒内自动拉起(崩溃自愈)。如果菜单栏图标长时间不在:终端跑 `~/PortalKit/.venv/bin/portalkit startup status`,或直接 `open -a PortalKit`。正常退出(⌘Q)不会自动拉起,属预期。

## 7. 通知太频繁/想全关?

设置 → 「异常与需要操作时系统通知」。成功状态从不通知(设计原则:安静运行);只有需要你操作时才提醒。

## 8. 支持哪些学校/门户?

见 README「当前支持的门户」。同一学校多个区域门户(如浙理工图书馆/教学区)各自独立配置,凭据可复用(引导窗口会自动预填同校已录账号)。

## 9. 怎么看详细日志?

菜单 → 「诊断与日志…」:三张健康卡 + 可读时间线(最新在上,可勾选"只看异常")。「复制诊断信息」产出脱敏 JSON(发维护者排查用);「导出脱敏诊断」保存为文件。日志文件本体在 `~/Library/Application Support/PortalKit/events.jsonl`(自动轮转,无敏感信息)。
